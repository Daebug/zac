## What this is

ZAC is an offline-first Android app for an archery club: membership tracking (expiry, renewals) and club funds (income/expenses). All data lives in on-device SQLite and optionally syncs to a separate backend server that is not in this repo. Expo SDK 58, Expo Router, npm (`package-lock.json`).

## Commands

```bash
npm start              # expo start (dev server)
npm run android        # expo start --android
npm run typecheck      # tsc --noEmit
npm run db:generate    # drizzle-kit generate — run after every change to src/db/schema.ts
npm run build:apk      # EAS cloud build, "preview" profile -> installable APK
```

- There is no test setup and ESLint is not installed; `npm run typecheck` is the only automated check. `npx expo lint` would prompt to install ESLint — ask before letting it.
- The app uses native modules outside Expo Go, so it needs a development build; `/android` is generated and git-ignored.

## Architecture

Imports use the `@/*` alias for `src/*`.

### Layers

- `src/db/` — Drizzle schema and the single `db` client (`expo-sqlite`, opened with `enableChangeListener: true`, which is what makes `useLiveQuery` screens refresh after writes).
- `src/data/` — the only place screens read or write domain data. Each file exports `useX()` live-query hooks for rendering, synchronous `getX()` reads for one-off use (e.g. form initial values), and mutation functions. Writes are synchronous Drizzle calls (`.run()`, `db.transaction`).
- `src/sync/` — sync engine (`sync.ts`), `SyncProvider`/`useSync` context, and live hooks for sync status and pending-change count.
- `src/lib/` — pure helpers (`utils.ts`: dates, status, money parsing), theme tokens, CSV/PDF import-export (`io.ts`), local photo storage.
- `src/components/` — `ui.tsx` (shared primitives) and `form.tsx` (`FormScreen`, `TextField`, `DateField`, `ChoiceField`). Screens are built from these plus `theme.ts` tokens rather than ad-hoc styles.
- `src/app/` — Expo Router screens only. Root `_layout.tsx` declares the stack: `(tabs)` plus detail screens and modal forms. Typed routes are enabled.

Forms use react-hook-form + zod; form values are strings and get converted to `MemberInput`/`TransactionInput` (`src/types.ts`) before reaching `src/data/`.

### Startup

`src/app/_layout.tsx` holds the splash screen until fonts settle and `useMigrations` has applied the bundled migrations, then calls `ensureSingletonRows()` (creates the `settings` and `sync_state` rows, both `id = 1`) and mounts `SyncProvider`.

### Migrations

`drizzle/` is generated by `drizzle-kit` and is bundled into the app: `babel-plugin-inline-import` and the `sql` source extension in `metro.config.js` let `drizzle/migrations.js` import `.sql` files as strings. Never hand-edit `drizzle/`; change `src/db/schema.ts` and run `npm run db:generate`. The folder must stay committed.

### Sync model (the invariants every write must respect)

- Synced tables (`members`, `transactions`, `settings`) carry `updated_at` and `dirty`. **Every mutation to synced fields must set `dirty: true` and a fresh `updated_at`** (`nowIso()`); otherwise the change never reaches the server.
- Deletes are soft: set `deleted_at` (+ `dirty`, `updated_at`). The row is physically removed only after a sync confirms the server has it. Consequently, **every read of members/transactions must filter `isNull(deleted_at)`**.
- IDs are client-generated UUIDs (`expo-crypto`). Dates are `yyyy-MM-dd` text; timestamps are ISO text.
- `members.photo_uri` is local-only: it is stripped from the push payload, and changing it must not mark the row dirty.
- A sync is one `POST {server_url}/zac/sync` that pushes all dirty rows and pulls everything changed since `last_pulled_at` (a server-clock cursor). When applying the response, a local row is left untouched if it is dirty and its `updated_at` differs from what was pushed (it was edited mid-sync); otherwise the server row wins. Adding a synced column means updating the schema, the explicit field lists in `applyResponse`, and the server.
- Login is `POST {server_url}/auth/login`; the token lives in `expo-secure-store`, not in SQLite. A 401 clears the token and reports `signed_out`. Connecting resets `last_pulled_at` to force a full pull.
- `sync()` de-duplicates concurrent calls and never throws; it resolves to a `SyncOutcome`. It runs on app launch and on every return to foreground, plus manually from the Sync settings screen.
- Cleartext HTTP is enabled on Android (`expo-build-properties`) because the server is typically reached by LAN IP.

### Domain rules

- Member status (`active` / `expiring_soon` / `expired`) is never stored; it is derived from `expiry_date` and the `expiry_warning_days` setting in `useMembers()`.
- Creating a member with a fee, or renewing one, also inserts a "Membership Fee" income transaction linked by `member_id`, in the same DB transaction. Deleting a member keeps those transactions.
- Category/payment-mode option lists and the input types live in `src/types.ts`.
- CSV member import is all-or-nothing: `parseMembersCsv` throws with the row number of the first bad row.
